# Support

Thank you for using Telepilot!

## Getting Help

| Channel | Use for |
|---|---|
| [GitHub Issues](../../issues) | Bug reports, confirmed defects |
| [GitHub Discussions](../../discussions) | Questions, ideas, show-and-tell |
| [CONTRIBUTING.md](CONTRIBUTING.md) | Guidance on opening pull requests |
| [SECURITY.md](SECURITY.md) | Reporting security vulnerabilities |

## Before Opening an Issue

1. Read the [README](README.md) — especially the **Troubleshooting** section.
2. Search [existing issues](../../issues) and [discussions](../../discussions) to see if your question has already been answered.
3. If you found a **security vulnerability**, do **not** open a public issue — follow the process in [SECURITY.md](SECURITY.md).

## What to Include in a Bug Report

- Your Telepilot version (or the commit SHA).
- Operating system and runtime version (Node.js / Python).
- Steps to reproduce the problem.
- Expected behaviour vs actual behaviour.
- Relevant log output (redact tokens and credentials before posting).

## Response Times

This is a community-maintained open-source project. Response times are best-effort:

| Severity | Target response |
|---|---|
| Security vulnerability | ≤ 72 hours (private channel) |
| Critical bug (data loss / crash) | ≤ 7 days |
| Standard bug / feature request | Best effort |

## Community Standards

Please follow our Code of Conduct (see [CONTRIBUTING.md](CONTRIBUTING.md)) in all support interactions.
